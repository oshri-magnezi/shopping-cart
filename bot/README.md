# super-price-bot

בוט Node.js שמקבל רשימת קניות ומדווח באיזו רשת סופרמרקט הסל יוצא הכי זול.

הנתונים נשאבים מ**קבצי המחירים הרשמיים** שהרשתות מחויבות לפרסם לפי חוק שקיפות המחירים — לא מסריקת אתרי קנייה. הקבצים מפורסמים פר-סניף, ולכן הבוט בוחר סניף בעיר שהוגדרה.

## הרצה

```bash
npm install
```

```bash
node src/index.js
```

מעקב מתמשך — מרענן את המחירים אוטומטית:

```bash
npm run watch
```

| דגל | משמעות |
|---|---|
| `--list <קובץ>` | רשימת קניות אחרת (ברירת מחדל `shopping-list.json`) |
| `--city "חיפה"` | עוקף את העיר שב-config |
| `--catalog <תיקייה>` | ייצוא מחירונים לאתר, קובץ לכל עיר (ראה למטה) |
| `--cities "א,ב,ג"` | הערים לייצוא (ברירת מחדל: העיר שב-config) |
| `--out <נתיב>` | נתיב לכתיבת `results.json` (למשל תיקיית האתר) |
| `--watch [דקות]` | לולאת רענון; ברירת מחדל 30 דקות |
| `--refresh` | מתעלם מהמטמון ומוריד מחדש |
| `--list-stores <key>` | מדפיס את סניפי הרשת, לבחירת `storeOverrides` |
| `--headful` | מריץ עם דפדפן גלוי, לדיבוג |

## הרשתות

11 רשתות מוגדרות ב-`config.json`. 8 מהן מחזירות מחירים בתל אביב:

| רשת | פורטל | הערה |
|---|---|---|
| שופרסל | `prices.shufersal.co.il` | פתוח |
| **חצי חינם** | `shop.hazi-hinam.co.il/Prices` | פורטל עצמאי; אין סניף בת"א — נבחר סניף המשלוחים הארצי |
| רמי לוי, יוחננוף, אושר עד, טיב טעם, דור אלון, פרש מרקט | Cerberus | התחברות עם שם משתמש ציבורי |
| קשת טעמים, סאלח דבאח, פוליצר | Cerberus | רשתות אזוריות — אין להן סניף בת"א שמפרסם מחירון |

הוספת רשת = שורה בקונפיג, בלי נגיעה בקוד:

```json
{ "key": "tivtaam", "displayName": "טיב טעם", "portal": "cerberus", "username": "TivTaam" }
```

פורטלים נתמכים: `shufersal`, `hazihinam`, `cerberus`, `victory`.

אם לא נמצא סניף בעיר, הריצו `--list-stores <key>` והגדירו מזהה ידני ב-`storeOverrides`.

## חיבור לאתר רשימת הקניות

**ייצוא המחירונים (הדרך המומלצת).** האתר מבצע את ההתאמה בעצמו מול הקטלוג המלא, כך שכל פריט שהמשתמש מקליד נמצא — ולא רק פריטים שהבוט תמחר מראש:

```bash
node src/index.js --catalog ../shopping-cart/public --cities "תל אביב,ראשון לציון,חיפה,ירושלים"
```

**קטלוג לכל עיר.** המחירים בקבצי השקיפות הם פר-סניף, ולכן קטלוג ארצי אחד היה מצטט מחירי תל אביב לקונה בראשון לציון. הייצוא כותב קובץ נפרד לכל עיר (`price-catalog-0.json`, `price-catalog-1.json`...) ואינדקס קטן, `price-catalog-index.json`, שמפרט את הערים ואת הרשתות שיש בכל אחת.

האתר טוען את האינדקס בכניסה, ומוריד רק את הקטלוג של העיר שנבחרה. החלפת עיר מחליפה גם את המחירים, גם את הסניפים וגם את רשימת הרשתות — לראשון לציון יש קשת טעמים ואין דור אלון, ולחיפה אין יוחננוף.

הקבצים ממוספרים ולא נקראים בשם העיר, כי שמות קבצים בעברית נשברים בין מערכות. כל עיר שוקלת 3-4.5MB (כ-80,000 מוצרים), שיורדים לכמיליון בייט בהעברה דחוסה.

**שיקול גודל:** git שומר כל גרסה של כל קובץ. ארבע ערים = כ-15MB לריצה, ולכן אין לדחוף רענון תכוף. לעדכון יומי או שבועי זה בסדר; לרענון שעתי עדיף לייצר את הקבצים ב-GitHub Actions בזמן הבנייה במקום לשמור אותם ב-repo.

---


**ייבוא רשימה מהאתר.** ייצאו את ה-localStorage מהאתר (DevTools → Application → Local Storage → `shopping-cart-data`) לקובץ, ואז:

```bash
node src/export-list.js exported.json shopping-list.json
```

הסקריפט מקבל את מבנה האתר המלא, את הרשימה הפעילה בלבד או מערך פריטים חשוף, ומצמצם אותו לחוזה של הבוט.

**ייצוא תוצאות לאתר.** `--out` כותב את הדו"ח לכל נתיב:

```bash
node src/index.js --watch 30 --out ../shopping-cart/public/price-results.json
```

### חוזה `results.json` — יציב, האתר יכול להסתמך עליו

```json
{
  "generatedAt": "2026-08-16T18:14:52.387Z",
  "city": "תל אביב",
  "items": [{ "name": "...", "quantity": 2 }],
  "comparison": {
    "rows": [{ "key", "displayName", "ok", "sharedTotal", "fullTotal", "foundCount", "itemCount", "storeName" }],
    "ranked": [ ... ],
    "winner": { "displayName": "רמי לוי", "sharedTotal": 53.4 },
    "savings": 7.4,
    "sharedIndexes": [0, 1, 3]
  },
  "chains": [{ "key", "ok", "storeName", "productCount",
               "matches": [{ "product": { "name", "price" }, "score", "alternatives": [] } | null] }]
}
```

`matches` מקביל לאינדקסים של `items`; `null` = הפריט לא נמצא ברשת הזו.
`sharedIndexes` הם הפריטים שנמצאו בכל הרשתות — לפיהם נקבע המנצח.

## סטיות מהמפרט המקורי

**ויקטורי אינה פעילה.** הפורטל `laibcatalog.co.il` לא מחזיר קבצי PriceFull לאף סניף ויקטורי, גם לא לתאריכים קודמים. האדפטר נכתב ותקין מבחינת ניווט, אך הרשת מחוץ לברירת המחדל.

**חצי חינם עברה פורטל.** החשבון `HaziHinam` ב-Cerberus מתאמת אך מחזיר אפס קבצים. הרשת מפרסמת בפורטל עצמאי `shop.hazi-hinam.co.il/Prices` — ולשם נכתב אדפטר ייעודי.

**כתובת Cerberus.** `url.retail.publishedprices.co.il` שבמפרט מגישה תעודת SSL לא תקפה. הכתובת העובדת היא `url.publishedprices.co.il`.

**שופרסל דרך endpoint ולא dropdowns.** האדפטר קורא ל-`/FileObject/UpdateCategory?catID=2&storeId=<id>` — ה-endpoint שהעמוד עצמו משתמש בו. עוקף דפדוף ורענון טבלה.

## מלכודות שנפתרו (שווה לדעת לפני שנוגעים בקוד)

**קידוד UTF-16.** חלק מהרשתות מפרסמות UTF-16 ולא UTF-8. פענוח כ-UTF-8 יוצר שמות תגיות עם בייטי null, והפרסר נופל עם שגיאה מטעה על קינון תגיות. `src/parse/gunzip.js` מזהה BOM ומריח בייטי null.

**מגבלות של fast-xml-parser.** ברירות המחדל שלו (`maxNestedTags: 100`, `maxEntityCount: 1000`) נועדו נגד XML bombs, אבל קטלוג אמיתי חוצה אותן בקלות. שתיהן הועלו ב-`src/parse/xml.js`.

**CORS בהורדה.** קבצי שופרסל וחצי חינם יושבים ב-Azure Blob (מקור אחר), ולכן `fetch` מתוך הדף נחסם. הורדות חוצות-מקור נעשות ישירות מ-Node; הורדות מאותו מקור עוברות דרך הדף כדי לשמר את ה-session של Cerberus.

**CSRF ב-Cerberus.** ה-endpoint של רשימת הקבצים דורש טוקן מה-DOM. בלעדיו הוא מחזיר 200 עם רשימה ריקה — כישלון שקט.

**קודי ערים.** שדה העיר בקבצים הוא בדרך כלל קוד למ"ס מספרי (5000 = תל אביב), לא שם. `src/fetch/cities.js` מתרגם.

**קיצורי ערים.** `ת"א` כתת-מחרוזת מסתתר בתוך "רמ**ת א**ליהו" ושלח סל תל-אביבי לסניף בראשון לציון. קיצורים קצרים נבדקים כמילה שלמה.

**`return` בלי `await` בתוך `try/finally`.** סוגר את הדף לפני שהפעולה הסתיימה ומייצר `TargetCloseError` מבלבל.

## איך עובדת ההתאמה

הניקוד משקלל **recall** (כמה מהשאילתה נמצא במוצר) יחד עם **precision** (כמה מהמוצר מוסבר ע"י השאילתה). ה-precision קריטי: בלעדיו "שמן זית" מקבל 1.0 גם עבור "שמפו שמן זית" ו"לאבנה עם שמן זית", וכלל "הזול מנצח" היה בוחר את השמפו.

קנסות נוספים: אחוז שומן סותר (3% מול 1%), **גודל אריזה סותר** (בקשה ל-1 ליטר מול קרטון 2 ליטר — אחרת הסל מתנפח פי שניים), מילת מפתח חסרה, ומוצר שהמילה הראשונה שלו — שם העצם המרכזי בעברית — לא מופיעה בשאילתה.

מוצר שלא עבר את הסף מסומן "לא נמצא" ואינו נספר. ההשוואה הקובעת היא **הסל המשותף** — רק פריטים שנמצאו בכל הרשתות — כדי שרשת לא "תנצח" רק בגלל שחסרים בה מוצרים.
